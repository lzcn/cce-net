# CCE-Net: Learning Fashion Compatibility with Context Conditioning Embedding

Official (cleaned) implementation of CCE-Net for fashion outfit compatibility modeling.

CCE-Net encodes every item with two branches:

1. a **GNN-based context conditioning branch**: `x -> LinearLN -> GNNs -> z_c`, which injects
   the context of the rest of the outfit through message passing, and
2. an **MLP-based general embedding branch**: `x -> LinearLN -> MLPs -> z_g`.

Compatibility is scored in the joint item space; optionally both embeddings are fused with a
coefficient `beta` (`--fuse-score --fuse-beta`). The model is trained with InfoNCE
(`train_cce_infonce.py`) or triplet loss (`train_cce_triplet.py`) over outfit tuples.

## Requirements

- Python >= 3.9
- [PyTorch](https://pytorch.org) (CUDA build recommended)
- [PyTorch Geometric](https://pytorch-geometric.readthedocs.io)
- numpy, scikit-learn, tqdm, tensorboard, lmdb

See `requirements.txt`. With conda (tested with torch 2.6.0+cu118 and PyG 2.6.1):

```bash
conda create -n cce-net python=3.10 -y
conda activate cce-net
pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cu118
pip install torch_geometric==2.6.1 numpy scikit-learn tqdm tensorboard lmdb
```

## Data

Experiments use the preprocessed datasets released on Hugging Face
([lzcn/outfit-datasets](https://huggingface.co/datasets/lzcn/outfit-datasets)), which contain
item images, pre-extracted ResNet-34 features (LMDB), and outfit tuple splits:

```bash
git clone https://huggingface.co/datasets/lzcn/outfit-datasets outfits-hf
```

The scripts expect the data one directory above the repository (`--data-dir ../outfits-hf`);
adjust `--data-dir` if you place it elsewhere.

Supported splits follow the `{dataset}/{split}` naming of the release, e.g.:

| `--data-set` | Description |
| --- | --- |
| `maryland-polyvore/original` | Maryland-PolyVore |
| `polyvore-outfits/disjoint` | PolyVore (UIUC), disjoint FITB split |
| `polyvore-outfits/nondisjoint` | PolyVore (UIUC), non-disjoint FITB split |
| `polyvore-u/original/tuples_519` | PolyVore-U personalized split |

> **Note:** `iqon-3000` in the dataset release currently ships image LMDBs only
> (no pre-extracted ResNet-34 features), so it cannot be used with this code out of the box.

Each tuple file stores one outfit per line as `uidx,size,item_1,...,item_K,type_1,...,type_K`
padded with `-1`; features are read from `features/resnet34/data.mdb` automatically.

## Usage

Train on Maryland-PolyVore with the InfoNCE loss (canonical hyperparameters):

```bash
bash scripts/maryland-polyvore-infonce.sh
```

or run directly:

```bash
python train_cce_infonce.py \
    --data-dir ../outfits-hf --data-set maryland-polyvore/original \
    --norm --feat-norm --neg-type-aware --trans-layer \
    --tau 0.10 --base-model GATConv --batch-size 128 --lr 0.1 \
    --num-layers 2 --neg-ratio 1 --num-neg 4 --neg-mode RandomMix \
    --log-dir runs/maryland-polyvore-infonce
```

Triplet loss variant:

```bash
bash scripts/maryland-polyvore-triplet.sh
```

Hybrid fusion variant on PolyVore (disjoint):

```bash
bash scripts/polyvore-outfits-disjoint-infonce.sh
```

Evaluate a trained checkpoint (`--test`) with random-mixed negatives or negatives generated by
replacing `k` items (`--neg-mode RandomReplace --num-replace k`):

```bash
python train_cce_infonce.py --data-dir ../outfits-hf --data-set maryland-polyvore/original \
    --test --load-trained runs/maryland-polyvore-infonce/checkpoints/net_best.pt
```

Checkpoints are written to `{log_dir}/checkpoints/net_{best,latest}.pt`; logs and TensorBoard
summaries to `{log_dir}`.

## Main options

| Option | Description |
| --- | --- |
| `--base-model` | context encoder backbone: `GATConv` (default), `GCNConv`, `GraphConv`, `PointConv` |
| `--num-layers` | number of GNN layers |
| `--without-context` | disable the context branch (general embedding only) |
| `--trans-layer` | add MLPs to the general embedding branch |
| `--full-graph` | symmetric context injection between all nodes |
| `--fuse-score --fuse-beta B` | fuse both branches: `B * z_c + (1 - B) * z_g` |
| `--norm` / `--feat-norm` | L2-normalize output / input features |
| `--tau` | temperature for the compatibility score |
| `--num-neg` | number of negative items per anchor |
| `--neg-mode` | negative generation: `RandomMix`, `RandomReplace`, or `Fix` |
| `--neg-ratio` | negative outfits per positive outfit during evaluation |

> Refactored with an LLM.
